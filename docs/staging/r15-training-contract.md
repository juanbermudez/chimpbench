# R15 training contract

Registered before teacher execution, 13 October 2026. This implements the narrow scope in r15-perceived-targets.md. No R15 model is loaded while R14 runs.

The live renderer and exporter use `r15Packet`, identity `resource-targets-v1`. Serializable context phase/kinds survive HTTP, JSON export and replay. Kind criteria contain fixed neutral activity words; target criteria use P5b neutral resource descriptions. Kind packet state is rendered without candidate targets so representative identity cannot change its social-timing selection or truncation. Both retain body, ongoing act and own-experience fields; this is a new packet, never an R11/R14-compatible adapter.

At each selected fresh decision, emit one kind row and at most one resource-target row, selected by a deterministic hash among multi-target resource groups before labels. The kind teacher is R11's original-menu conditional distribution, summed into offered kinds and normalized; excluded kind mass is reported, not silently credited. It requires the existing 2,000 minimum / 20,000 maximum redraws, target 500 same menus and minimum 100. Learner asks do not claim realized teacher RNG/pick reconstruction. Kept/arrived choices are not fresh labels.

The resource-target teacher is counterfactual valuation imitation on the fixed shown menu: each option retains its current rules raw value including persistence, plus redrawn uniform candidate jitter and the existing belief distribution, then the published-score clamp/rounding and maximum. Use 2,000 deterministic redraws keyed by record ID, canonical action/target tie order, and no world RNG. This teacher is not the original rules' choice probability on a wider menu and is not an ecological reward or wild preference. Its finite sample can assign zero to rare alternatives; report counts and redraws. Body/social gates stay unchanged. Scores, reasons and teacher diagnostics never enter packets.

Each row records parent decision, seed, animal, split, phase, exact packet and context hashes, teacher and normalized soft label. Training/development use existing animal split on 48/7, seed21 evaluation only; phases of one decision stay together. Assembly rejects duplicate rows, split leakage, incorrect packet/context parity and identity mismatches. It writes new files and a manifest; it never mixes old flat packets. The unchanged R11 soft-label trainer trains a newly named R15 adapter from base, three epochs, seeds7/11 separately. The wrapper checks data hashes/identities and R14's lock/state plus running model processes before importing any model module. Its default prints the exact command; explicit run is guarded. No old-adapter compatibility claim.

Focused checks use synthetic valid contexts and small pure teacher draws only. Production collection, tokenizer counts, model parity, training, cost and behavior validation remain future work after R14 is idle.

Collection command (after R14 is idle): `pnpm exec tsx scripts/r15-contexts.ts sample --seed 48 --ticks 1400 --limit 16`, then seed7. The sampler reuses R8's fresh rules-decision hooks, 30-day rules burn-in, fixed probability .02 and at most16 selected fresh decisions per command by default (hard limit64; at most1400 post-burn-in ticks). It labels the exact new request at each selected state; it does not change controllers or apply its labels. `assemble --parts <s48.jsonl>,<s7.jsonl> --out <new-root>` writes split files, hashes, manifest and a reviewable training command. A small bounded sample may have empty development data; training refuses until an adequate registered sample exists. Actual collection is refused while R14's lock or running state is present.

Ordinary browser/server providers explicitly refuse marked R15 contexts until a compatible adapter route exists. The experimental headless runner validates the new adapter identity instead. Default-off providers and packets are unchanged.

Operational amendment before production collection: collection and assembly CLIs require a clean committed checkout. Assembly requires every part's metadata to match the current source commit, W50 parameter hash, row count, seed and file hash; the final manifest binds both part and metadata hashes. Both train and development must contain at least one kind and one target row, reported separately. Zero retained activity mass is counted as `zero-retained-kind-mass` and emits no rows for that decision.

The 1,400-tick limit applies only to sampling. The 30-day rules burn-in costs another 172,800 ticks; sidecars report both, and collection stops after a 30-minute wall budget checked at each tick. There is no production collection while R14 is active. Training uses the same exclusive `artifacts/r14-chain.lock` as R14 and rechecks model activity after acquiring it. A training attempt has a six-hour wall cap; timeout terminates its entire process group and leaves partial files for inspection, never silently restarting or overwriting. Preparation prints a command; run refuses active work rather than waiting.

Preflight continuation registered before execution: `python3 -B training/decide_ft/r15_preflight.py --root <root>` prepares the command; `--run` takes the shared lock, checks idle again and starts one supervised worker with a 45-minute wall cap. It refuses an existing preflight directory, preserving failed evidence. Maximum input is 20,000 train/development rows. Every exact live packet and its deterministic training-recipe option permutation is counted by the existing real R8 tokenizer path; each must be at most 1,280 tokens. No held-out seed21 scoring is part of this preflight.

Numerical fixture selection is deterministic SHA256 ID order, up to six development rows per phase, both original and recipe-permuted menus. Reuse the existing parity procedure (`classify_text` versus `common.action_logits`) at fp32 and fp16 MPS with identical token IDs. The fp32 maximum absolute probability gap is 0.0001. Installed GLiNER `classify_text` computes softmax in fp16, whereas actual `AdapterModel/common.score` casts logits to fp32; this known API-rounding comparison allows 0.001 gap and 0.001 sum error for the half-precision API only. On the same single base model also compare fp32 versus fp16 (maximum 0.005), and actual training bf16 autocast versus serving fp16 (maximum 0.02). All probabilities must be finite, nonnegative, at most one, and sum within 0.00001 of one. These explicit precision tolerances are engineering acceptance bounds, not accuracy guarantees; a failure stops the stage rather than widening them. Model-processor counts must match the tokenizer-only counts on every fixture packet. No optimizer or adapter is loaded during preflight.

Persist exact packet hashes, per-row token counts, numerical arrays/gaps, phase/split/animal coverage, limits, elapsed time, source hashes, dataset manifest/train/dev hashes, pinned base revision, tokenizer/config assets, provider/package source hashes and package versions. The default receipt is `preflight/result.json`; success requires all evidence and unchanged identities. `train_r15.py --run` validates the receipt after acquiring the shared lock and injects its hash into a separate immutable `contexts/training-manifest.json`, which the unchanged R11 trainer copies into the completed adapter manifest. A tiny dataset can pass implementation preflight but is only a smoke dataset: inspect coverage before registering any enlarged collection, and claim no behavioral quality from these checks.

Runtime/completion amendment before model execution: only MPS with FlashDeBERTa disabled is qualified. The supervisor passes the selected interpreter explicitly, and the worker checks the actual interpreter and virtual environment before model imports. After the trainer exits successfully, the supervisor revalidates preflight, three-epoch completion, data and weight hashes while retaining the shared lock, then atomically adds `adapter_config_sha256` and `preflight_runtime_sha256` to the final adapter manifest. The latter is SHA256 of UTF-8 `json.dumps(runtime, sort_keys=True, separators=(',', ':'))`. A trainer manifest without these completion bindings is not eligible for app startup.
