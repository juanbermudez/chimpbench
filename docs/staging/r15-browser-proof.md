# R15 browser proof registration

Registered 13 October 2026 before implementation checks, on base d763020. This is an app integration proof, not a behavioral quality result. The real run remains pending until the existing R14 chain has stopped and a completed, preflight-qualified R15 adapter is configured on the app server.

The verifier owns one new isolated browser context against a local, already configured server. It opens only `?r15=1&test=1`, checks the fresh seed-48 field world, fixed five living animals aged 8+, lockstep and disabled saving, starts the selected R15 provider through its existing UI if needed, and presses Play through the UI. It never starts a server or a second model, changes actions, supplies answers or invokes tick hooks. An existing ready provider is reused and recorded. Shared chain states and the model lock must exclude R14 before Chrome starts; only a live R15-app lock is permitted.

Budget: one run, at most 3,600 seconds from launch including startup, with at most 660 seconds waiting for readiness. Watch 4× advances at most 960 fifteen-second ticks in that hour (fewer during inference). A browser-side UI pause watchdog additionally stops at 1,300 ticks or the wall deadline; an observed tick above 1,400 fails. Each sample checks the selected speed. There are no retries of a failed real run without an explicit continuation registration. Implementation allows three bounded syntax/pure fixture check rounds and one scoped TypeScript check; no browser, model, simulation, full suite or build during preparation.

Evidence: durable run status, JSONL raw HTTP request/answer records with real per-stage token counts, unique completed decision traces and current applied action/target observations, initial/final state, source identity, served module hashes, and full-app/Mind/model screenshots. A small `?test=1` read-only hook clones the recent 20 traces and the five controlled animals; it cannot alter the world. Acceptance requires exact adapter identity throughout, normalized distributions, legal offered selected targets accepted by the simulation, a live matching model-sourced action/target, at least one applied two-stage choice, observed lockstep waiting, and repeated applied inputs for one chimp with both body and own-experience changes. Missing target or recurrence coverage fails rather than substituting fabricated decisions.

On success, failure or handled interruption, pause through the UI, preserve partial evidence, close only this browser, and leave the externally owned server/worker running. Screenshots require subsequent human/agent visual inspection; automatic capture alone does not establish visual acceptance. Browser receipts are an integration trace, not the headless deterministic replay journal.
